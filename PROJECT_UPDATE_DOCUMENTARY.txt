🎬 Phase 6: Multi-Layout Photo Upload & Soundtrack Architecture
================================================================================

THE MISSION:
Enhance the Couple Gallery app to support 4 strictly validated photo arrangements,
local computer photo uploads (JPG, JPEG, PNG, WebP), optional local MP3 soundtrack
uploads with a custom audio player, and PostgreSQL media persistence.

--------------------------------------------------------------------------------
1. PHOTO LAYOUT SELECTION & ARRANGEMENT
--------------------------------------------------------------------------------
Four distinct layout options with visual preview cards and exact photo counts:
- Solo (`layout-1`): Exactly 1 photo (large single image, 220px height)
- Horizontal (`layout-2h`): Exactly 2 photos side by side (2 equal columns)
- Vertical (`layout-2v`): Exactly 2 photos stacked (1 column, 2 rows)
- Window Grid (`layout-4`): Exactly 4 photos in a 2-by-2 grid

--------------------------------------------------------------------------------
2. STRICT PHOTO COUNT VALIDATION (FRONTEND & BACKEND)
--------------------------------------------------------------------------------
- Photo count must match the chosen layout exactly. Submissions with too few or
  too many photos are rejected immediately.
- Frontend displays tailored warning banners:
  * Solo (0 photos): "Please upload exactly 1 photo for the Solo layout."
  * Horizontal (!= 2): "The Horizontal layout requires exactly 2 photos."
  * Vertical (!= 2): "The Vertical layout requires exactly 2 photos."
  * Window Grid (< 4): "The Window Grid layout requires exactly 4 photos. Please upload the remaining photos."
  * Window Grid (> 4): "Maximum of 4 photos allowed for the Window Grid layout. Remove the excess photos."
- "Save Memory" button remains disabled until required photo count is reached
  and memory title is entered.
- Layout change confirmation: If user selects photos and changes layout, the app
  warns them before clearing selections to prevent accidental data loss.
- Backend replicates all validation rules with HTTP 400 responses, preventing direct
  API bypass or URL injection.

--------------------------------------------------------------------------------
3. LOCAL PHOTO UPLOADS
--------------------------------------------------------------------------------
- File picker accepts local image files (.jpg, .jpeg, .png, .webp).
- Online image URLs, external links, and unsupported formats are rejected.
- Multi-photo selection enabled when layout allows multiple slots.
- Live client-side previews in the exact layout arrangement before saving.
- Each photo slot supports individual "Replace" and "Remove" actions.
- Real-time counter: "X of Y photos selected" (turns green upon completion).
- Binary file signature verification on backend (magic bytes) to ensure authenticity.

--------------------------------------------------------------------------------
4. CUSTOM LOCAL MP3 MUSIC PLAYER
--------------------------------------------------------------------------------
- Optional MP3 soundtrack upload from computer (.mp3 only, up to 20 MB).
- External music links, YouTube, and Spotify streams are explicitly blocked.
- Live audio preview in the Add Memory form before submitting.
- Custom-designed MusicPlayer component on every saved memory with a soundtrack:
  * Play / Pause button
  * Interactive draggable seek bar with gradient fill
  * Current time & total duration (MM:SS format)
  * Volume control slider & instant mute button
  * Animated equalizer wave indicator while playing
  * No autoplay on page load
  * Global single-audio coordinator: playing one track automatically pauses any
    other playing memory across the gallery.
  * If a memory has no MP3, no broken or empty player is rendered.

--------------------------------------------------------------------------------
5. BACKEND & POSTGRESQL PERSISTENCE
--------------------------------------------------------------------------------
- PostgreSQL migration (`backend/migrations/001_add_media.sql`):
  * `photos TEXT[] NOT NULL DEFAULT '{}'` (ordered array of uploaded server paths)
  * `music_path TEXT` (file path for MP3 soundtrack, NULL if none)
  * `music_name TEXT` (original filename for display)
- Multer multipart storage writes files to disk (`backend/uploads/photos`, `backend/uploads/music`).
- Static file serving via `express.static` with HTTP Range support for audio seeking.
- Automated cleanup on DELETE: removing a memory from the database automatically
  unlinks and deletes its associated photo and MP3 files from disk.

--------------------------------------------------------------------------------
6. VERIFICATION & TESTS

🎬 Phase 7: Authentication, User Profile & Floating Add Memory UI
================================================================================

THE MISSION:
Add email/password authentication with username and strengthened password rules,
per-account private memories in PostgreSQL, a rightmost navbar profile badge
with circle avatar + name and click-to-edit profile modal, and a floating
"+ Add Memory" button at the bottom-right of the gallery page.

--------------------------------------------------------------------------------
1. AUTHENTICATION & PASSWORD STRENGTH
--------------------------------------------------------------------------------
- Sign Up requires:
  * Username (used as display name in the navbar)
  * Valid Email Address (unique per user)
  * Strengthened Password: must be at least 6 characters AND include both
    letters (`[a-zA-Z]`) and numbers (`[0-9]`).
  * Confirm Password match check.
- Log In verifies email and password against salted `crypto.scrypt` hashes in
  PostgreSQL and returns an HMAC-SHA256 signed session token.
- Flow:
  1. Log In / Sign Up screen (`AuthPage.jsx`)
  2. Animated Landing Page with self-drawing heart and "Open gallery" button (`App.jsx`)
  3. Personal Gallery (`Gallery.jsx`)

--------------------------------------------------------------------------------
2. NAVBAR PROFILE & EDIT PROFILE MODAL
--------------------------------------------------------------------------------
- Email is not displayed in the navbar.
- Rightmost side of the navbar displays a clickable profile pill containing:
  * Circle profile picture (`avatar_path` or initial avatar placeholder)
  * User's name (`username`)
- Clicking the profile picture or name opens the "Edit Profile" modal:
  * Edit name (`username`)
  * Upload a profile picture from the computer (`.jpg`, `.jpeg`, `.png`, `.webp`)
    stored in `backend/uploads/avatars` and persisted in `users.avatar_path`.

--------------------------------------------------------------------------------
3. FLOATING "+ ADD MEMORY" BUTTON
--------------------------------------------------------------------------------
- Moved "+ Add Memory" out of the navbar to the bottom-right corner of the
  gallery page (`position: fixed; right: 2.2rem; bottom: 2.2rem;`).
- Added continuous vertical floating animation (`@keyframes fabFloat`).

--------------------------------------------------------------------------------
4. POSTGRESQL MIGRATIONS (`002_add_auth.sql` & `003_add_user_profile.sql`)
--------------------------------------------------------------------------------
- `users` table: `id`, `username`, `email`, `password_hash`, `avatar_path`, `created_at`
- `memories.user_id` foreign key linking memories privately to each user account.

🎬 Phase 8: Customizable Sticky Notes (Page & Picture Placement)
================================================================================

THE MISSION:
Allow users to insert customizable sticky notes anywhere on the gallery page or
directly inside any memory picture, with 4 light pastel colors (white, pink,
purple, yellow), drag-and-drop repositioning, and PostgreSQL persistence.

--------------------------------------------------------------------------------
1. STICKY NOTE BUTTON & FLOATING DOCK POSITION
--------------------------------------------------------------------------------
- Positioned in the bottom-right floating action dock (`.floating-actions-dock`)
  right above the `+ Add Memory` button so all creation controls are grouped in
  one accessible spot.
- Includes a live color palette pill (`Note color:`) above the `📌 + Sticky Note`
  button so the user can pre-select their preferred note color before placing it.
- Also provides a quick `📌 + Note` button in the bottom-right corner of every
  individual photo slot on hover for one-click picture note insertion.

--------------------------------------------------------------------------------
2. PLACEMENT ANYWHERE ON THE PAGE OR INSIDE ANY PICTURE
--------------------------------------------------------------------------------
- Clicking `📌 + Sticky Note` activates placement mode with a helper banner at
  the top of the gallery.
- Clicking anywhere on the gallery page pins a page-level sticky note at that
  exact `(pos_x, pos_y)` coordinate.
- Clicking inside any photo slot pins a compact picture-level sticky note
  directly onto that specific photo (`memory_id` + `photo_index`).
- Both page-level and picture-level sticky notes can be freely dragged by their
  header bar (`📌`) and automatically save their updated coordinates.

--------------------------------------------------------------------------------
3. 4 LIGHT PASTEL COLORS & LIVE CUSTOMIZATION
--------------------------------------------------------------------------------
- Every sticky note supports 4 light pastel colors:
  * Soft White (`white`)
  * Light Pink (`pink`)
  * Light Purple (`purple`)
  * Light Yellow (`yellow`)
- Each note header features 4 circular color swatches to switch colors on the fly,
  auto-saving text textarea, and a delete (`✕`) button.

--------------------------------------------------------------------------------
4. POSTGRESQL PERSISTENCE (`004_add_sticky_notes.sql`)
--------------------------------------------------------------------------------
- `sticky_notes` table: `id`, `user_id`, `memory_id`, `photo_index`, `content`,
  `color`, `pos_x`, `pos_y`, `created_at`, `updated_at`.
- REST endpoints: `GET /api/notes`, `POST /api/notes`, `PUT /api/notes/:id`,
  and `DELETE /api/notes/:id`.
